# 使用 mise 替代系统包管理器统管运行环境

传统面板通过系统级包管理器（如 `apt` / `yum`）来全局安装 Python、PHP 等运行环境，极易引发多版本依赖冲突，并在卸载时产生难以清理的残留。为了追求更好的环境隔离，我们决定全面弃用系统包管理器来管理语言运行时，转而引入由 Rust 编写的多语言版本管理器 **`mise`**（原 `rtx`）。

- **依赖安装与编译**：所有语言运行时的下载、源码编译均交给 `mise` 处理（如底层依赖缺失可通过 `apt` 兜底补齐，但语言核心由 `mise` 闭环管理）。
- **完全隔离运行 (Execution Shim)**：EasyServer 面板托管的所有实体（例如 Web 服务器的 PHP-FPM 配置、后台执行的 Cron 定时脚本、守护进程等），必须使用 `mise exec <语言>@<版本> -- <命令>` 作为唯一执行入口，彻底隔离环境变量 `PATH`，防止被系统或全局其他进程干扰。
- **全局回退 (Global Default)**：我们依然保留“设为默认版本”的概念，通过执行 `mise use -g <语言>@<版本>` 来实现，但这**仅为方便用户在 SSH 终端操作或执行未受控脚本**提供兜底，在面板的自动化业务流中不依赖该全局设定。

这一决策意味着 EasyServer 的“Runtime（运行环境）”不再与服务器宿主机的状态深度绑定，具备了类似容器化隔离的安全性和一致性，同时避免了 Docker 在低配服务器上的高昂内存开销和文件读写权限等痛点。
